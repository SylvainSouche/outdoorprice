    50→
    51→## Pourquoi les 7 autres sites ne sont pas considérés comme fonctionnels
    52→
    53→Le `README.md` liste uniquement **Bergzeit** et **Sport Bittl** comme sites
    54→supportés. Ce n'est pas une omission : c'est le reflet de tests réels. Voici,
    55→pour chaque site exclu, le symptôme observé et la cause racine.
    56→
    57→### Ekosport — bloqué à l'enrichissement
    58→
    59→- **Recherche** : fonctionne (24 produits renvoyés par Algolia).
    60→- **Enrichissement** : les pages produit `https://www.ekosport.fr/...` sont
    61→  derrière Cloudflare. Le scraper tente Playwright en repli, ce qui ajoute 8 à
    62→  15 s par page et finit par timeout si plus de 6 produits sont enrichis.
    63→- **Cause racine** : les endpoints Intershop
    64→  (`/INTERSHOP/rest/.../algolia-configurations` et `algolia-api-key`) sont
    65→  eux-mêmes derrière Cloudflare, mais le scraper les résout via
    66→  `fetchJsonViaPlaywright()`. Ça marche, mais dès qu'on attaque les pages
    67→  produit, Cloudflare réagit plus agressivement.
    68→- **Ce qui marcherait** : ne pas faire l'enrichissement sur Ekosport, ou
    69→  n'enrichir que 2-3 produits, ou attendre une IP résidentielle.
    70→
    71→### Montaz — recherche OK mais enrichissement non testé
    72→
    73→- **Recherche** : 24 produits renvoyés. Tout est dans des attributs `data-*`.
    74→- **Enrichissement** : non testé de bout en bout depuis le sandbox à cause
    75→  des timeouts cumulés sur les autres sites en parallèle.
    76→- **Risque** : les pages produit de Montaz sont rendues côté serveur, donc
    77→  l'enrichissement devrait marcher en théorie — mais le site n'expose pas
    78→  toujours un JSON-LD complet, ce qui oblige à tomber sur les tableaux
    79→  techniques génériques (moins fiables).
    80→
    81→### Snowleader — recherche OK, enrichissement non testé
    82→
    83→- **Recherche** : 24 produits via GraphQL Magento (en-tête `Store:
    84→  Store_View_COM_FR`).
    85→- **Enrichissement** : non testé de bout en bout depuis le sandbox.
    86→- **Piège** : Snowleader renvoie 403 après deux recherches rapprochées — le
    87→  scraper respecte un délai minimum, mais en cas d'appels rapprochés
    88→  (refresh UI, multi-onglets) la deuxième requête peut échouer.
    89→
    90→### Glisshop — recherche OK via Playwright, enrichissement non testé
    91→
    92→- **Recherche** : 20 produits renvoyés. Le moteur est Doofinder en WebSocket
    93→  Phoenix LiveView — axios seul ne voit rien. Le scraper charge la homepage
    94→  via Playwright, ouvre le layer Doofinder, tape la requête, attend les
    95→  cartes `.dfd-card-type-product` et les extrait.
    96→- **Enrichissement** : non testé. Les pages produit de Glisshop sont en
    97→  Angular rendu côté client ; le JSON-LD `<script type="application/ld+json">`
    98→  standard devrait être présent après rendu Playwright.
    99→- **Coût** : chaque recherche Glisshop nécessite un Chromium headless, ce qui
   100→  ajoute ~5 s et ~80 Mo de RAM. En parallèle avec les autres sites, ça
   101→  consomme.
   102→
   103→### Sport Conrad — bloqué (API 500 + HTML 403)
   104→
   105→- **Recherche** : l'API Makaira `POST https://sport-conrad.makaira.io/search/public`
   106→  répond **500** depuis le sandbox. Le corps envoyé est correct (count et
   107→  offset en chaînes, `customFilter` obligatoire), mais le serveur renvoie
   108→  un 500 sans explication.
   109→- **Repli HTML** : `GET https://www.sport-conrad.com/en/search?q=...` est
   110→  protégé par Cloudflare → 403 sur axios. Le scraper tente Playwright, mais
   111→  Cloudflare le bloque aussi (challenge JS non résolu).
   112→- **Ce qui marcherait** : depuis une IP résidentielle, l'API Makaira devrait
   113→  répondre (le protocole est documenté dans `upload/PROTOCOLES.md`).
   114→
   115→### Tradeinn — bloqué (Cloudflare 403)
   116→
   117→- **Recherche** : `POST https://www.tradeinn.com/listado.php` renvoie 403
   118→  dès le préfetch OPTIONS de Cloudflare. Le scraper tente Playwright, mais
   119→  Cloudflare le bloque aussi.
   120→- **Cause racine** : Tradeinn est l'un des sites les plus agressifs contre
   121→  les data-centers — Cloudflare challenge même les requêtes Playwright avec
   122→  un user-agent navigateur réaliste.
   123→- **Ce qui marcherait** : IP résidentielle + headers complets
   124→  (`Origin`, `Referer`, `User-Agent` Chrome réel). Le protocole est
   125→  documenté : `action=buscador_google`, extraction du prix depuis
   126→  `attributes.price_all_<a>_to_<b>` (23 grilles par pays, le groupe France
   127→  identifié).
   128→
   129→### Au Vieux Campeur — bloqué (HTTP 403 + Playwright KO)
   130→
   131→- **Recherche** : `POST https://api.sensefuel.live/search/<compte>` renvoie
   132→  403 même avec `Origin`, `Referer` et `X-Requested-With` corrects.
   133→- **Repli Playwright** : `fetch()` exécutée depuis Chromium échoue avec
   134→  `Failed to fetch` — probablement à cause d'un challenge Cloudflare ou
   135→  d'une validation CSP.
   136→- **Cause racine** : le serveur SenseFuel vérifie quelque chose au-delà des
   137→  headers (empreinte TLS, challenge JS exécuté sur `auvieuxcampeur.fr`
   138→  avant l'appel API, cookie de session).
   139→- **Ce qui marcherait** : exécuter d'abord un `GET https://www.auvieuxcampeur.fr/`
   140→  pour récupérer les cookies, puis réinjecter ces cookies dans l'appel API
   141→  SenseFuel. À implémenter si le site devient une priorité.

   145→## Détail des protocoles
   146→
   147→Pour chaque site, voici le protocole implémenté (cf. `upload/PROTOCOLES.md`
   148→pour le relevé original complet, y compris les pièges spécifiques).
   149→
   150→### Bergzeit — état applicatif inline (Vue)
   151→
   152→**Statut** : FONCTIONNE
   153→
   154→#### Point d'entrée
   155→```
   156→GET https://www.bergzeit.fr/search/?q=<terme>&p=<page>
   157→```
   158→
   159→#### Authentification
   160→Aucune.
   161→
   162→#### Requête
   163→Aucun corps. Les données sont dans `window.__initialAppState` de la page
   164→servie. Le scraper extrait ce bloc `<script>` et l'évalue via `Function()`
   165→(c'est un objet littéral JS, pas du JSON strict).
   166→
   167→#### Champs utiles
   168→
   169→| Champ | Rôle |
   170→|-------|------|
   171→| `modules.productsListPage.elementsList[]` | liste des produits |
   172→| `data.name` | libellé |
   173→| `data.url` | lien produit (relatif → résolu via `absUrl()`) |
   174→| `data.price.current` | prix payé |
   175→| `data.price.old` | ancien prix — vaut « 0,00 € » hors promotion |
   176→| `data.price.previous` | prix conseillé du fabricant (PAS un prix barré) |
   177→| `data.images[0].src` | image |
   178→| `data.brand.name` | marque |
   179→| `data.variations[import:manufacturer_size]` | tailles |
   180→
   181→#### Repli
   182→Si l'évaluation échoue (corps trop gros), on extrait uniquement le tableau
   183→`elementsList` via bracket-counting et on le passe à `JSON.parse()`. En
   184→dernier ressort, le JSON-LD de la page liste les produits **sans aucun prix**
   185→(documenté dans `upload/PROTOCOLES.md`).
   186→
   187→#### Pièges
   188→- `data.price.previous` est le prix conseillé du fabricant, pas un ancien prix.
   189→- Le JSON-LD liste les produits mais SANS aucun prix.
   190→- `ms=true&filters` ne renvoie que les facettes : pas de variante « produits ».
   191→- Les tailles doubles « 42.5|43 » doivent être séparées.
   192→

   195→### Sport Bittl — sélecteurs CSS
   196→
   197→**Statut** : FONCTIONNE
   198→
   199→#### Point d'entrée
   200→```
   201→GET https://www.sport-bittl.com/search.php?query=<terme>
   202→```
   203→
   204→#### Authentification
   205→Aucune. Page HTML rendue côté serveur.
   206→
   207→#### Requête
   208→Aucun corps. Parsing direct avec cheerio.
   209→
   210→#### Champs utiles
   211→
   212→| Champ | Rôle |
   213→|-------|------|
   214→| `div.product-thumb-info` | carte produit |
   215→| `span.product-name` | libellé |
   216→| `span.product-price.is-reduced` | prix payé (uniquement si promo) |
   217→| `span.product-price.is-original` | prix conseillé, suffixé « RRP » |
   218→| `span.product-brand` | marque |
   219→| `a.product-title` | lien produit |
   220→
   221→#### Pièges
   222→- `is-reduced` n'existe que sur les articles en promotion : s'y limiter
   223→  perd les produits plein tarif. On lit donc `span.product-price` générique
   224→  en repli.
   225→- Chaque carte porte DEUX spans de prix (un régulier, un barré si promo).
   226→- `is-price-type-1` n'a pas été élucidé (ignoré).
   227→- Le `<h1>` annonce le nombre de résultats entre parenthèses — utile pour
   228→  vérifier qu'on n'a pas perdu de produits.

   232→### Ekosport — Algolia via Intershop
   233→
   234→**Statut** : recherche OK, enrichissement bloqué (Cloudflare sur les pages produit)
   235→
   236→#### Point d'entrée
   237→```
   238→POST https://<APP_ID>-dsn.algolia.net/1/indexes/*/queries
   239→```
   240→Index : `EKO-FR-PRD-LIVE-product-fr`
   241→
   242→#### Authentification
   243→Clé publique à durée limitée (15 jours), obtenue à chaud sur deux endpoints
   244→Intershop derrière Cloudflare :
   245→```
   246→GET /INTERSHOP/rest/WFS/EKO-FR-Site/-;loc=fr_FR/algolia-configurations  → appId, index
   247→GET /INTERSHOP/rest/WFS/EKO-FR-Site/-;loc=fr_FR/algolia-api-key         → { data: { apiKey, expiresIn } }
   248→```
   249→Ces deux endpoints sont résolus via `fetchJsonViaPlaywright()` (Chromium
   250→headless charge la page, parse le JSON depuis `<pre>`).
   251→
   252→#### Requête
   253→```json
   254→{
   255→  "requests": [{
   256→    "indexName": "EKO-FR-PRD-LIVE-product-fr",
   257→    "params": "query=…&hitsPerPage=24&page=0&attributesToRetrieve=name,marque,prices,imageUrl,altImagesUrl,couleur,genre,v_l_pointure_eu"
   258→  }]
   259→}
   260→```
   261→`page` est numéroté à partir de 0. On restreint `attributesToRetrieve` : le
   262→site demande 70 facettes et l'analytique, sans usage pour un comparateur.
   263→
   264→#### Champs utiles
   265→
   266→| Champ | Rôle |
   267→|-------|------|
   268→| `prices.sale` | prix payé |
   269→| `prices.list` | prix catalogue |
   270→| `marque` | marque (et non « brand ») |
   271→| `couleur`, `genre` | tableaux, valeurs préfixées d'un souligné : « _Bleu » |
   272→| `v_l_pointure_eu` | pointures EU (trois systèmes cohabitent) |
   273→| `altImagesUrl.L` | image 600 px ; `imageUrl` n'est qu'une vignette de 80 px |
   274→
   275→#### Enrichissement en lot
   276→```
   277→GET <REST>/productstock?sku=A&sku=B&variations=false → [{ sku, inStock, webStock }]
   278→```
   279→
   280→#### Pièges
   281→- `imageUrl` fait 80 px : inutilisable en liste.
   282→- Les valeurs de facettes portent un souligné initial, qui passerait dans
   283→  l'affichage si on oublie de le retirer.
   284→- Trois systèmes de tailles dans le même enregistrement — US, EU, Mondopoint.
   285→- Aucun EAN dans l'index.
   286→- **Cloudflare bloque les pages produit** : l'enrichissement échoue ou
   287→  nécessite Playwright (lent, ~10 s par page).
   288→

   327→### Snowleader — GraphQL Magento
   328→
   329→**Statut** : recherche OK
   330→
   331→#### Point d'entrée
   332→```
   333→POST https://api.snowleader.com/graphql/
   334→```
   335→Store view : `Store_View_COM_FR` (porte la langue française).
   336→
   337→#### Authentification
   338→Aucune. En-tête `Store: Store_View_COM_FR` pour choisir la langue.
   339→
   340→#### Requête
   341→```graphql
   342→query productList($search:String!, $currentPage:Int=1, $pageSize:Int=24){
   343→  products(search:$search, currentPage:$currentPage, pageSize:$pageSize){
   344→    total_count
   345→    items {
   346→      __typename
   347→      id
   348→      sku
   349→      name
   350→      url_key
   351→      image { url }
   352→      price_range {
   353→        minimum_price {
   354→          final_price { value currency }
   355→          regular_price { value currency }
   356→        }
   357→      }
   358→      ... on ConfigurableProduct {
   359→        configurable_options {
   360→          attribute_code
   361→          values { value_index label }
   362→        }
   363→      }
   364→      bazaarvoice_rating { rating }
   365→    }
   366→  }
   367→}
   368→```
   369→Six champs demandés là où le site en demande une cinquantaine.
   370→
   371→#### Champs utiles
   372→
   373→| Champ | Rôle |
   374→|-------|------|
   375→| `price_range.minimum_price.final_price.value` | prix payé |
   376→| `price_range.minimum_price.regular_price.value` | prix catalogue |
   377→| `url_key + « .html »` | lien produit (la forme courte redirige) |
   378→| `bazaarvoice_rating` | note client, obtenue à la source |
   379→| `configurable_options` | tailles — exige le fragment `... on ConfigurableProduct` |
   380→
   381→#### Repli
   382→```
   383→GET https://api.snowleader.com/search/ajax/suggest/?q=…&___store=…
   384→```
   385→Autocomplétion en GET, sans authentification, quelques produits seulement.
   386→
   387→#### Pièges
   388→- `configurable_options` n'appartient pas à `ProductInterface` : sans
   389→  fragment, GraphQL refuse la requête ENTIÈRE.
   390→- L'autocomplétion `min_price` vaut 49,90 quand `final_price` vaut 99,90 —
   391→  seul `final_price` est le prix payé.
   392→- Aucun EAN publié, nulle part.
   393→- **403 après deux recherches rapprochées** — respecter un délai minimum
   394→  entre les appels.

   398→### Glisshop — Doofinder (Phoenix LiveView WebSocket)
   399→
   400→**Statut** : recherche OK via Playwright
   401→
   402→#### Point d'entrée
   403→```
   404→wss://eu1-layer.doofinder.com/layer/1/websocket?hashid=<HASHID>&…
   405→```
   406→Index : un hashid par couple langue/devise — neuf déclarés.
   407→
   408→#### Authentification
   409→Aucune sur le WebSocket. L'API REST, elle, répond « request not
   410→authenticated » et la configuration de la boutique ne contient aucune clé :
   411→cette voie est close.
   412→
   413→#### Requête
   414→Trame Phoenix :
   415→```
   416→["5","51","lv:df-<mount_id>","event",
   417→  { type:"form", event:"search-submit", value:"search%5Bquery%5D=<terme>" }]
   418→```
   419→La réponse arrive en diffs successifs, décodés par `src/core/liveview.js`.
   420→
   421→#### Implémentation réelle
   422→Le scraper ne décode pas la trame Phoenix. À la place, il utilise
   423→Playwright pour :
   424→1. Charger la homepage `https://www.glisshop.com/`.
   425→2. Cliquer sur `input[name=searchText]` (ouvre le layer Doofinder plein écran).
   426→3. Taper dans `.dfd-searchbox-input`.
   427→4. Valider.
   428→5. Attendre `.dfd-card-type-product` et extraire les cartes.
   429→
   430→#### Champs utiles
   431→
   432→| Champ | Rôle |
   433→|-------|------|
   434→| `data-product-id` | identifiant, aussi collé en fin d'URL produit |
   435→| `.dfd-value-link` | URL absolue du produit |
   436→| `.dfd-card-sku` | marque |
   437→| `.dfd-card-title` | libellé |
   438→| `.dfd-card-price--sale[data-value]` | prix promo |
   439→| `.dfd-card-price[data-value]` | prix catalogue |
   440→| `.dfd-card-flag[data-discount]` | badge promo |
   441→| `.dfd-card-thumbnail img[src]` | image |
   442→| `gtin13` (fiche produit, JSON-LD) | EAN |
   443→
   444→#### Pièges
   445→- Une extraction par expressions régulières ne marche pas : 20 liens pour
   446→  18 prix et 10 libellés, sans appariement par position.
   447→- Les gabarits sont partagés entre composants par renvoi numérique, et
   448→  l'héritage est récursif.

   609→
   610→Rien, ou presque — et c'est l'enseignement principal. Trois régularités tout
   611→de même, apparues sur plusieurs boutiques indépendamment :
   612→

   614→Vieux Campeur porte le prix catalogue, `min_price` chez Snowleader ne
   615→correspond à rien d'affiché, `previous` chez Bergzeit est le prix conseillé

   618→donc faire gagner la boutique à tort.
   619→

   621→dépôt.** `visitorid`, `userIds`, `trackFingerPrint` : générés à l'exécution,
   622→jamais recopiés d'un relevé. Des tests le vérifient.
   623→
   624→**La page servie ment souvent sur son contenu.** Montaz range tout dans des
   625→attributs, Bergzeit dans un état applicatif inline, Glisshop et Au Vieux
   626→Campeur ne servent qu'une coquille. « 0 prix dans la page » n'a jamais voulu
   627→dire « pas de prix ».

   756→## Alltricks — formulaire POST (server-side) + Twitter Typeahead
   757→
   758→**Statut** : **BLOQUÉ** par Cloudflare sur `/search` depuis le sandbox.
   759→Fonctionne depuis une IP résidentielle.
   760→
   761→### Point d'entrée
   762→```
   763→POST https://www.alltricks.fr/search
   764→```
   765→Form-encoded : `s=<terme>`
   766→
   767→### Authentification
   768→Aucune. Mais le POST vers `/search` déclenche un challenge Cloudflare JS que
   769→Playwright ne peut pas résoudre depuis une IP data-center.
   770→
   771→### Particularité : /recherche n'est PAS protégé
   772→La page `https://www.alltricks.fr/recherche` (qui est en fait une 404) ne
   773→déclenche PAS le challenge Cloudflare. Elle contient le formulaire de
   774→recherche, ce qui permet de le remplir et le soumettre. Le submit POST vers
   775→`/search`, lui, est protégé.
   776→
   777→### Implémentation
   778→1. Chromium charge `https://www.alltricks.fr/recherche` (sans Cloudflare).
   779→2. Accepter les cookies (banner Didomi — `#didomi-notice-agree-button`).
   780→3. Cliquer sur `input.search.tt-input` (Twitter Typeahead), taper la requête.
   781→4. Submit (Enter).
   782→5. Attendre jusqu'à 30s que le challenge Cloudflare se résolve (titre passe
   783→   de "Un instant…" à un titre normal). Depuis une IP résidentielle, ça
   784→   prend 1-2s. Depuis le data-center, le challenge ne se résout jamais.
   785→6. Une fois la page de résultats chargée, extraire les liens `/F-XXX/P-XXX`.
   786→
   787→### URL des produits
   788→```
   789→https://www.alltricks.fr/F-<catId>-<catSlug>/P-<prodId>-<prodSlug>
   790→```
   791→ex : `https://www.alltricks.fr/F-32743-etriers-de-frein/P-412486-etrier_de_frein_avant_shimano_105_br_r7000_noir`
   792→
   793→### Champs utiles (à confirmer depuis une IP résidentielle)
   794→Le HTML étant rendu côté serveur, on extrait les cartes produit en cherchant
   795→les liens `a[href*="/P-"]` puis en remontant au conteneur parent qui contient
   796→l'image et le prix.
   797→
   798→| Sélecteur | Rôle |
   799→|-----------|------|
   800→| `a[href*="/P-"]` | lien produit (contient URL + titre) |
   801→| parent (5 niveaux) | conteneur carte (image + prix) |
   802→| `img[src]` dans parent | image |
   803→| `[class*="price"]` dans parent | prix |
   804→
   805→### Pièges
   806→- Le formulaire est un POST, pas un GET — l'URL `/search?Search=castelli`
   807→  retourne un 404 (paramètre `Search` au lieu de `s`).
   808→- La classe `tt-input` indique Twitter Typeahead : pendant la frappe, des
   809→  suggestions apparaissent dans une dropdown. Ne pas les confondre avec les
   810→  résultats de la page `/search`.
   811→- Cloudflare bloque le POST `/search` depuis le data-center, même via
   812→  Playwright avec spoofing de navigator.webdriver. Le challenge nécessite
   813→  une IP résidentielle.
   814→- Didomi cookie banner bloque le focus — accepter les cookies avant de
   815→  cliquer sur le champ de recherche.
   816→- Bazaarvoice (`apps.bazaarvoice.com`) est l'API reviews — pas utile pour
   817→  le comparateur, on l'ignore.

   916→Sites valides : `bergzeit, ekosport, glisshop, montaz, snowleader, sportbittl,
   917→sportconrad, tradeinn, auvieuxcampeur`.
   918→
   919→> Les 9 scrapers sont chargés dans `src/lib/scraper/registry.ts`. Si vous
   920→> voulez désactiver un site (par exemple pour ne pas attendre 30 s sur
   921→> Tradeinn à chaque appel), commentez sa ligne dans le tableau `SCRAPERS`.

   924→
   925→## Ajouter un site
   926→
   927→1. D'abord **vérifier en live** que le site est scrapable :
   928→   ```bash
   929→   bun -e 'import {fetchHtml} from "./src/lib/scraper/http"; fetchHtml("https://site.com/search?q=test").then(r => console.log(r.status, r.html.length))'
   930→   ```
   931→   - Si 403 / "Just a moment..." → Cloudflare, le fallback Playwright
   932→     tentera de le résoudre.
   933→   - Si 200 et `< 5 KB` → probablement un challenge, Playwright requis.
   934→   - Si 200 et `> 100 KB` → OK, on peut parser le HTML.
   935→
   936→2. Créer `src/lib/scraper/sites/<nouveausite>.ts` implémentant l'interface
   937→   `Scraper` (voir `bergzeit.ts` ou `sportbittl.ts` comme template).
   938→
   939→3. L'ajouter au tableau `SCRAPERS` dans `src/lib/scraper/registry.ts`.
   940→
   941→4. L'ajouter aux types `SiteId` et au dictionnaire `SITES` dans
   942→   `src/lib/scraper/types.ts`.
   943→
   944→5. Ajouter sa cible Makefile :
   945→   `check-<nouveausite>: ; @$(MAKE) check-site SITE=<nouveausite> Q="$(Q)"`.
   946→
   947→6. Documenter le protocole dans ce fichier (section « Détail des protocoles »).
