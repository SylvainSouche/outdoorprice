    77→
    78→```
    79→┌─────────────────────────────────────────────────────────────────┐
    80→│                     Browser (Client)                             │
    81→│                                                                  │
    82→│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────────┐    │
    83→│  │ Search   │  │ Sidebar  │  │ Product  │  │ Logs Panel │    │
    84→│  │ Header   │  │ Filters  │  │ Grid     │  │            │    │
    85→│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └─────┬──────┘    │
    86→│       │              │              │              │            │
    87→│       └──────────────┴──────────────┴──────────────┘           │
    88→│                          │ useQuery (React Query)               │
    89→│                          ▼                                      │
    90→│                   fetch("/api/search")                          │
    91→└──────────────────────────┬──────────────────────────────────────┘
    92→                           │ HTTP POST
    93→                           ▼
    94→┌─────────────────────────────────────────────────────────────────┐
    95→│                    Next.js Server (API Route)                    │
    96→│                                                                  │
    97→│  /api/search/route.ts                                           │
    98→│    1. Validate query + sites                                     │
    99→│    2. Check in-memory cache (LRU, 2-min TTL)                    │
   100→│    3. Call aggregateMatched(query, { onlySites })               │
   101→│    4. Cache result + return JSON                                │
   102→└──────────────────────────┬──────────────────────────────────────┘
   103→                           │
   104→                           ▼
   105→┌─────────────────────────────────────────────────────────────────┐
   106→│                    Scraper Engine (registry.ts)                   │
   107→│                                                                  │
   108→│  Phase 1: SEARCH (parallel)                                      │
   109→│    ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐            │
   110→│    │bergzeit │ │ekosport │ │glisshop│ │ ... 20   │            │
   111→│    │.ts      │ │.ts      │ │.ts     │ │ scrapers  │            │
   112→│    └────┬────┘ └────┬────┘ └────┬────┘ └────┬─────┘            │
   113→│         │           │           │            │                    │
   114→│         ▼           ▼           ▼            ▼                    │
   115→│    ┌─────────────────────────────────────────────┐             │
   116→│    │  http.ts (axios + Playwright fallback)       │             │
   117→│    │  browserPool.ts (shared Chromium)            │             │
   118→│    └─────────────────────────────────────────────┘             │
   119→│                          │                                       │
   120→│                          ▼ ProductResult[] (raw, per-site)      │
   121→│                                                                  │
   122→│  Phase 2: ENRICH (top N=6 per site)                             │
   123→│    ┌─────────────────────────────────────────────┐             │
   124→│    │  enrich.ts                                    │             │
   125→│    │  - fetch product page                         │             │
   126→│    │  - extract: JSON-LD, microdata, meta tags,   │             │
   127→│    │    specs table, breadcrumbs, variations      │             │
   128→│    │  - guessBrandFromTitle, classifyTaxonomy      │             │
   129→│    └─────────────────────────────────────────────┘             │
   130→│                          │ EnrichedItem[]                       │
   131→│                          ▼                                       │
   132→│  Phase 3: MATCH (cross-site grouping)                           │
   133→│    ┌─────────────────────────────────────────────┐             │
   134→│    │  matcher.ts (Union-Find)                      │             │
   135→│    │  Cascade: EAN → vetoes → cosmetic → multi    │             │
   136→│    └─────────────────────────────────────────────┘             │
   137→│                          │ MatchedProduct[]                     │
   138→│                          ▼                                       │
   139→│  filters.ts → DynamicFilters (facets for UI)                    │
   140→└─────────────────────────────────────────────────────────────────┘
   141→```
   142→
   143→### Data flow summary
   144→
   145→```
   146→User types "Dynafit" → submittedQuery set
   147→  → useQuery fires POST /api/search
   148→    → registry.aggregateMatched("Dynafit", { onlySites })
   149→      → 20 scrapers run in parallel (Phase 1: search)
   150→      → top 6 products per site get enriched (Phase 2: enrich)
   151→      → all products matched cross-site (Phase 3: match)
   152→      → filters.ts builds DynamicFilters
   153→    → response cached (2-min TTL)
   154→  → data.products + data.filters arrive at client
   155→    → useMemo(filtered) applies client-side filters:
   156→      - userOff (site checkbox toggling — no re-fetch)
   157→      - onlyPromos, onlyInStock, minPrice, maxPrice, minSites
   158→      - activeBrands/Categories/... (8 dynamic filter sets)
   159→      - liveFilter (sidebar search field — exact-text substring match)
   160→    → MatchedProductCard[] rendered
   161→```

   165→## 3. Scraper Engine
   166→
   167→### `types.ts` — Shared types + client-safe site registry
   168→
   169→**Role:** Defines all TypeScript interfaces shared between server and client. Also holds the `SITES` record (client-safe metadata only — no imports of axios/playwright).
   170→
   171→**Key types:**
   172→- `SiteId = string` — plain string (drop-in friendly)
   173→- `SiteMeta { id, name, baseUrl, country, currency, accent, groups }` — per-shop metadata
   174→- `ProductResult` — raw product from a scraper
   175→- `ProductMetadata` — enriched data (brand, category, ean, weight, colors, sizes, etc.)
   176→- `MatchedProduct` — grouped product with multiple `ProductOffer[]`
   177→- `Scraper { site, capabilities, search() }` — scraper interface
   178→- `DynamicFilters` — facets for the UI sidebar
   179→- `ShopGroup` — group definition
   180→
   181→**`SITES: Record<string, SiteMeta>`** — 20 entries with `groups` field (e.g. `groups: ["outdoor"]` or `groups: ["cycling"]` or `groups: ["outdoor", "cycling"]`). Client-safe because it contains **only data** — no function imports.
   182→
   183→**Design choice:** `SITES` lives in `types.ts` (not `sites/index.ts`) because the client UI (`page.tsx`) needs it for rendering badges, and importing from `sites/index.ts` would transitively pull in axios/playwright (Node-only).
   184→
   185→### `http.ts` — HTTP client with anti-bot headers + Playwright fallback
   186→
   187→**Role:** Shared HTTP layer for all HTML-based scrapers.
   188→
   189→**Key functions:**
   190→- `pickUserAgent()` — random from 5 browser User-Agents
   191→- `createHttpClient({ timeoutMs, referer })` — axios instance with realistic headers (Sec-Ch-Ua, Accept-Language, etc.)
   192→- `fetchHtml(url, opts)` — main fetcher:
   193→  - If `SCRAPE_USE_PLAYWRIGHT=1` → straight to Playwright
   194→  - Otherwise: axios → if blocked (status ≥ 400 or HTML contains "just a moment"/"cloudflare") → retry via Playwright
   195→- `parsePrice(raw)` — handles FR ("1 234,56 €"), DE ("1.234,56 EUR"), EN ("1,234.56"), Swiss ("CHF 1'234.50")
   196→- `absUrl(href, base)` — relative→absolute URL resolver
   197→- `cleanTitle(raw)` — collapse whitespace
   198→- `fetchJsonViaPlaywright(url)` — for JSON rendered inside `<pre>` (Cloudflare-protected APIs)
   199→- `fetchJsonPostViaPlaywright(apiUrl, opts)` — boots Chromium, solves Cloudflare, then runs `fetch()` inside `page.evaluate`
   200→
   201→**Design choices:**
   202→- Robots.txt **not consulted** (personal-use tool, not a public indexer — see file header)
   203→- `SCRAPE_JITTER=1` adds 200-700ms random delay to look human
   204→- Proxy support via `PROXY_URL` env (HTTP/HTTPS/SOCKS5)
   205→
   206→### `enrich.ts` — Product page metadata extraction
   207→
   208→**Role:** Fetches each product page and extracts structured `ProductMetadata`.
   209→
   210→**Key functions:**
   211→- `enrichProduct(p, signal)` — main entry, merges data from:
   212→  1. **JSON-LD** (`<script type="application/ld+json">` with `@type Product`)
   213→  2. **Microdata** (`[itemtype*=schema.org/Product]` + `itemprop`)
   214→  3. **Meta tags** (`og:brand`, `product:gtin`, etc.)
   215→  4. **Specs table** (`dl/dt/dd`, `table tr`, `.specs li`)
   216→  5. **Breadcrumb** (`schema.org/BreadcrumbList`)
   217→  6. **Variations** (color swatches, size selectors)
   218→- `guessBrandFromTitle(title)` — scans `KNOWN_BRANDS` list (100+ brands: Dynafit, Castelli, Shimano, etc.) + model→brand inference (e.g. "Speedgoat" → "Hoka")
   219→- `parseWeightGrams(raw)` — "850 g" / "1.2 kg" → grams
   220→- `extractColorsFromTitle(title)` — recognizes `/<color>` suffixes, `couleur: X` patterns
   221→
   222→**Design choices:**
   223→- Always returns an object (never throws) — on network failure, falls back to `guessBrandFromTitle(title)`
   224→- `ENRICH_TOP_N_PER_SITE = 6` — only top 6 per site enriched (performance)
   225→- Calls `classifyTaxonomy()` to normalize raw categories into consistent sport/category/subcategory/range
   226→
   227→### `matcher.ts` — Cross-site Union-Find matcher
   228→
   229→**Role:** Groups `ProductResult` entries from different sites into `MatchedProduct` (one logical product = multiple offers).
   230→
   231→**Matching cascade (in priority order):**
   232→1. **Strong ID** (EAN/GTIN/MPN ≥6 chars) → score 1.0, reason "ean"
   233→2. **Hard vetoes** (reject regardless of other scores):
   234→   - `gender-mismatch` — "Speedgoat 7 W" vs "Speedgoat 7 M"
   235→   - `product-line-mismatch` — GTX vs non-GTX, Mid vs Low, Pro vs base
   236→   - `model-version-mismatch` — Speedgoat 6 vs 7
   237→3. **Same-site cosmetic variant** — same brand + title Jaccard ≥ 0.85 → reason "cosmetic-variant"
   238→4. **Multi-criteria cross-site score** — brand 0.30 + category 0.20 + sport 0.15 + subcategory 0.10 + range 0.10 + title sim 0.15. Match if ≥ 0.55 AND title sim ≥ 0.4
   239→5. **Title-only similarity** ≥ 0.85 → reason "title-similarity"
   240→6. **Brand + model tokens** — same brand + Jaccard ≥ 0.5 → reason "brand+model"
   241→
   242→**Design choices:**
   243→- `STOP_TOKENS` strips FR/EN/DE color words, gender words, generic product nouns, outdoor colorway names
   244→- `stripColorSuffix(title)` truncates at last gender marker or first `/`
   245→- Union-Find with path compression
   246→- Results sorted by `siteCount DESC`, then `minPrice ASC`
   247→
   248→### `registry.ts` — Orchestrator
   249→
   250→**Role:** Runs all scrapers → enriches → matches.
   251→
   252→**Key functions:**
   253→- `aggregateSearch(query, opts)` — runs all scrapers in parallel
   254→  - HTTP scrapers: concurrent with random stagger (≤800ms)
   255→  - Playwright scrapers: limited to `MAX_PARALLEL_PLAYWRIGHT` (default 3) via worker-pool cursor
   256→- `aggregateMatched(query, opts)` — full workflow:
   257→  1. **Search phase** → `aggregateSearch()`
   258→  2. **Enrich phase** → `runPool(toEnrich, 8, enrichProduct)` (8 concurrent enrichments)
   259→  3. **Match phase** → `prepareItems()` → `matchProducts()`
   260→  4. Returns `{ products, filters, rawResults, phases: { searchMs, enrichMs, matchMs }, anySuccess }`
   261→
   262→**Design choices:**
   263→- `runScraperWithRetry` — aborts after `PER_SITE_TIMEOUT` (30s default, 60s for challenge sites); retries once if empty
   264→- `ScraperError` caught per-site — no error crashes the aggregate
   265→- **No demo fallback** — if all sites fail, response is empty
   266→- `DEBUG_DUMP=1` writes raw per-site JSON + `matched.json` to `debug/`
   267→
   268→### `filters.ts` — DynamicFilters builder
   269→
   270→**Role:** Builds facet lists for the UI sidebar from `MatchedProduct[]`.
   271→
   272→- `buildDynamicFilters(products)` — counts brands, categories, subcategories, sports, ranges, genders, colors, sizes, attributes, priceRange. Caps each list (e.g. brands.slice(0, 30)).
   273→- `normalizeSizeValue(raw)` — "42" → "eu:42", "US 10.5" → "us:10.5", "M" → "m"
   274→
   275→### `groups.ts` — Group management
   276→
   277→**Role:** Builtin group metadata + custom group persistence.
   278→
   279→- `DEFAULT_GROUPS` — derived from `BUILTIN_GROUP_META` + each `SITES[id].groups` field
   280→- `loadCustomGroups()` / `saveCustomGroups()` — localStorage persistence
   281→- `getSitesForGroup(groups, groupId)` — returns site IDs for a group
   282→
   283→**Design:** Adding a shop to a group = setting `groups: ["cycling"]` in `sites/<id>.ts`. No edit to `groups.ts` needed.
   284→
   285→### `sites/index.ts` — Barrel file + auto-derived lookups
   286→
   287→**Role:** Imports all 20 scrapers, derives lookups.
   288→
   289→- `SCRAPERS: Scraper[]` — array of all scrapers
   290→- `PLAYWRIGHT_SITES` — derived from `SCRAPERS.filter(s => s.capabilities?.usesPlaywright)`
   291→- `CHALLENGE_SITES` — derived from `SCRAPERS.filter(s => s.capabilities?.challenge)`
   292→- `SCRAPER_BY_SITE` — `Record<siteId, Scraper>`
   293→
   294→### `browserPool.ts` — Shared Chromium instance
   295→
   296→**Role:** Single Chromium instance with reusable per-call contexts.
   297→
   298→- `acquireContext(referer?)` — lazily launches browser, creates new `BrowserContext`
   299→- `releaseContext(context)` — closes context, keeps browser alive
   300→- Anti-detection: hides `navigator.webdriver`, fakes `navigator.languages`/`plugins`/`vendor`, spoofs WebGL
   301→
   302→**Design:** ~80 MB total memory instead of ~80 MB × N (one browser, N contexts).
   303→
   304→### `playwright.ts` — Playwright wrapper
   305→
   306→**Role:** Fallback for JS-rendered / Cloudflare-protected sites.
   307→
   308→- `fetchHtmlWithPlaywright(url, opts)` — 2 attempts; waits for challenge self-resolution (up to 12s), then races for product selectors
   309→- Anti-Cloudflare: never uses `networkidle` (Cloudflare keeps long-polling)
   310→
   311→### `taxonomy.ts` — Category normalizer
   312→
   313→**Role:** Normalizes raw category strings into consistent taxonomy.
   314→
   315→- `classifyTaxonomy(...inputs)` → `{ sport?, category?, subcategory?, range? }`
   316→- `SPORT_RULES` — 12 sports (Ski de randonnée, Alpinisme, Escalade, Trail, VTT, etc.)
   317→- `CATEGORY_RULES` — ~20 categories (Peaux de ski, Chaussures, Sacs à dos, etc.)
   318→- `RANGE_RULES` — Compétition, Performance, Loisir, Ultralight, Freeride
   319→
   320→### `error.ts` — Typed scraper errors
   321→
   322→**Role:** Structured error class with categories for the logs panel.
   323→
   324→- `ScraperErrorCategory = "blocked" | "timeout" | "empty" | "network" | "parse" | "auth" | "unknown"`
   325→- `ScraperError.inferCategory(message, statusCode)` — e.g. HTTP 403 → "blocked"
   326→- `isRetryable()` — timeout, network, transient blocked
   327→

   330→## 4. API Routes
   331→
   332→### `POST /api/search` — Main search endpoint
   333→
   334→**Request body:**
   335→```json
   336→{
   337→  "query": "castelli giro",
   338→  "onlySites": ["all4cycling", "probikeshop"],
   339→  "group": "cycling"
   340→}
   341→```
   342→
   343→**Response:**
   344→```json
   345→{
   346→  "query": "castelli giro",
   347→  "totalProducts": 15,
   348→  "products": [MatchedProduct, ...],
   349→  "filters": DynamicFilters,
   350→  "durationMs": 8234,
   351→  "phases": { "searchMs": 3200, "enrichMs": 4100, "matchMs": 934 },
   352→  "anySuccess": true,
   353→  "demo": false,
   354→  "sites": [{ "id": "all4cycling", "name": "All4cycling", "status": "ok", "count": 24, "durationMs": 2800 }],
   355→  "cached": false
   356→}
   357→```
   358→
   359→**Key behaviors:**
   360→- `query.length >= 2` required
   361→- `X-Custom-Groups` header: base64 JSON of user's custom groups (server can't read localStorage)
   362→- In-memory LRU cache (2-min TTL, 50 entries)
   363→- If group is selected but empty → short-circuits with empty response
   364→
   365→### `GET/POST/DELETE /api/groups` — Group management
   366→
   367→- **GET** → `{ groups: [...DEFAULT_GROUPS, ...customFromHeader] }`
   368→- **POST** `{ id, name, sites }` → validates, returns `{ group: ShopGroup }`
   369→- **DELETE** `?id=<groupId>` → refuses builtin groups

   375→### `page.tsx` — Single-page application (2000+ lines)
   376→
   377→**State variables (17 total):**
   378→
   379→| Variable | Type | Purpose |
   380→|---|---|---|
   381→| `query` | string | Search input value |
   382→| `submittedQuery` | string | Actually triggers useQuery |
   383→| `groups` | ShopGroup[] | Builtin + custom |
   384→| `activeGroupId` | string | Active group ("all" by default) |
   385→| `sortKey` | SortKey | Sort order |
   386→| `onlyPromos` | boolean | Filter: on-sale only |
   387→| `onlyInStock` | boolean | Filter: in-stock only |
   388→| `minPrice` | number\|null | Price floor |
   389→| `maxPrice` | number\|null | Price ceiling |
   390→| `minSites` | number | Min sites offering product |
   391→| `liveFilter` | string | Free-text product filter (sidebar search field — filters displayed results without re-fetching) |
   392→| `userOff` | Set<SiteId> | Deselected sites (client-side) |
   393→| `showShopTree` | boolean | Treeview expand/collapse |
   394→| `activeBrands` | Set<string> | Selected brands |
   395→| `activeCategories` | Set<string> | Selected categories |
   396→| ... (8 filter sets total) | | |
   397→| `showDebug` | boolean | Unused (dead code) |
   398→
   399→**Data flow:**
   400→```
   401→query → onSubmit → submittedQuery → useQuery → data
   402→                                                  ↓
   403→filtered = useMemo(data.products + all filters)
   404→                                                  ↓
   405→filtered.map(p => <MatchedProductCard>)
   406→```
   407→
   408→**Key design:** `selectedSites` is **NOT** in `queryKey` — toggling a site checkbox filters client-side without re-fetching.

   428→### `csv.ts` — CSV export

   430→- `exportMatchedCsv(products)` — one row per offer (18 columns)
   431→- `exportCategorizedCsv(products)` — one row per product (26 columns, debug mode)

   434→### `i18n.tsx` — Internationalization
   435→
   436→- `LangProvider` — React context, persists to localStorage
   437→- `useLang()` → `{ lang, setLang, t }`
   438→- `t(key, params)` — supports `{param}` interpolation and `{n} word{s}` pluralization
   439→- 4 languages: FR, EN, ES, DE (~60 keys each)
   440→
   441→### `logs.ts` — Client log buffer
   442→
   443→- In-memory buffer (max 500 entries, FIFO)
   444→- `logInfo/logWarn/logError(site?, message)` — push entries
   445→- `subscribeLogs(listener)` — pub/sub for the LogsPanel
   446→- `logSearchResults(sites)` — parses API response, emits per-site logs with human-friendly error messages
   447→
   448→### `cache.ts` — In-memory LRU cache
   449→
   450→- `getCached(query, sites, group)` / `setCached(query, data, ...)`
   451→- 50 entries max, 2-min TTL
   452→- Key = `query | sorted-sites-csv | group`
   453→
   454→### `debug.ts` — Debug session writer
   455→
   456→- `createDebugSession(query)` → creates `debug/<timestamp>_<slug>/`
   457→- `dumpSearchResults(dir, query, results)` → per-site JSON
   458→- `dumpMatchedResults(dir, matched, phases)` → `matched.json`

   462→## 7. Chrome Extension
   463→
   464→### Architecture
   465→
   466→```
   467→extension/
   468→├── manifest.json              # MV3, devtools_page
   469→├── devtools.html/js           # Creates "Shop Protocol" DevTools panel
   470→├── panel.html/js              # Panel UI + capture logic
   471→├── protocol-generator.js      # Builds protocol.md from captured requests
   472→├── background.js              # Minimal service worker
   473→└── vendor/jszip.min.js        # Bundled JSZip for archive download
   474→```
   475→
   476→### Capture pipeline
   477→
   478→1. **Record** — `chrome.devtools.network.onRequestFinished` captures all XHR/fetch/WebSocket traffic
   479→2. **Categorize** — `isSearchRequest()` (sophisticated GraphQL-aware heuristic) / `isProductRequest()` (URL patterns) / WebSocket / Other
   480→3. **Filter noise** — 30+ filters for analytics, Shopify telemetry, app scripts, fonts, reviews
   481→4. **Auto-derive shop name** — from inspected tab URL via `chrome.devtools.inspectedWindow.eval`
   482→5. **Generate protocol.md** — markdown with: sample product, JSON-LD extraction, product card HTML, field list, WS frames
   483→6. **Download archive (.zip)** — protocol.md + capture.json + manifest.json + README.md + requests/ folder
   484→
   485→### Key heuristics
   486→
   487→- **GraphQL false-positive filtering** — distinguishes `query searchProducts(...)` from `query GetSlideCartOffers(...)` by inspecting operation names
   488→- **HTML response handling** — 50KB limit (was 5KB), JSON-LD ItemList extraction, product card HTML extraction, result count detection from `<title>`

   544→## 10. Key Design Decisions
   545→
   546→### 1. Drop-in scraper workflow
   547→Adding a shop = 1 file + 2 one-line edits. No Makefile/groups.ts changes needed.
   548→
   549→### 2. Capability-driven registry
   550→`PLAYWRIGHT_SITES`, `CHALLENGE_SITES`, timeouts — all derived from each scraper's `capabilities` field. No hard-coded lists.
   551→
   552→### 3. Three-phase pipeline
   553→Search → Enrich → Match, each timed. Enrichment bounded to top-N per site (perf); all products participate in matching.
   554→
   555→### 4. Union-Find matcher with hard vetoes
   556→Gender, product-line, model-version vetoes prevent false positives that pure weighted scoring would create.
   557→
   558→### 5. Client-side site filtering
   559→Toggling a site checkbox filters locally without re-fetching. `queryKey` excludes `selectedSites`.
   560→
   561→### 6. SITES in types.ts (client-safe)
   562→The `SITES` record contains only data (no function imports) so the UI can import it without pulling Node-only deps into the client bundle.
   563→
   564→### 7. Single shared Chromium
   565→One browser instance, reusable contexts (~80 MB total vs ~80 MB × N).
   566→
   567→### 8. No demo fallback
   568→If all sites fail, response is empty. Real errors shown.
   569→
   570→### 9. In-memory LRU cache
   571→2-min TTL, 50 entries. Reduces redundant scrapes during rapid UI interactions.
   572→
   573→### 10. Self-contained release
   574→`output: "standalone"` in next.config.ts. `build-release.sh` bumps 4 version files in lockstep.
