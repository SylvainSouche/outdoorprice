   143→   143→   143→### Data flow summary
   144→   144→   144→
   145→   145→   145→```
   146→   146→   146→User types "Dynafit" → submittedQuery set
   147→   147→   147→  → useQuery fires POST /api/search
   148→   148→   148→    → registry.aggregateMatched("Dynafit", { onlySites })
   149→   149→   149→      → 20 scrapers run in parallel (Phase 1: search)
   150→   150→   150→      → top 6 products per site get enriched (Phase 2: enrich)
   151→   151→   151→      → all products matched cross-site (Phase 3: match)
   152→   152→   152→      → filters.ts builds DynamicFilters
   153→   153→   153→    → response cached (2-min TTL)
   154→   154→   154→  → data.products + data.filters arrive at client
   155→   155→   155→    → useMemo(filtered) applies client-side filters:
   156→   156→   156→      - userOff (site checkbox toggling — no re-fetch)
   157→   157→   157→      - onlyPromos, onlyInStock, minPrice, maxPrice, minSites
   158→   158→   158→      - activeBrands/Categories/... (8 dynamic filter sets)
   159→   159→   159→      - liveFilter (sidebar search field — exact-text substring match)
   160→   160→   160→    → MatchedProductCard[] rendered
   161→   161→   161→```

   165→   165→   165→## 3. Scraper Engine
   166→   166→   166→
   167→   167→   167→### `types.ts` — Shared types + client-safe site registry
   168→   168→   168→
   169→   169→   169→**Role:** Defines all TypeScript interfaces shared between server and client. Also holds the `SITES` record (client-safe metadata only — no imports of axios/playwright).
   170→   170→   170→
   171→   171→   171→**Key types:**
   172→   172→   172→- `SiteId = string` — plain string (drop-in friendly)
   173→   173→   173→- `SiteMeta { id, name, baseUrl, country, currency, accent, groups }` — per-shop metadata
   174→   174→   174→- `ProductResult` — raw product from a scraper
   175→   175→   175→- `ProductMetadata` — enriched data (brand, category, ean, weight, colors, sizes, etc.)
   176→   176→   176→- `MatchedProduct` — grouped product with multiple `ProductOffer[]`
   177→   177→   177→- `Scraper { site, capabilities, search() }` — scraper interface
   178→   178→   178→- `DynamicFilters` — facets for the UI sidebar
   179→   179→   179→- `ShopGroup` — group definition
   180→   180→   180→
   181→   181→   181→**`SITES: Record<string, SiteMeta>`** — 20 entries with `groups` field (e.g. `groups: ["outdoor"]` or `groups: ["cycling"]` or `groups: ["outdoor", "cycling"]`). Client-safe because it contains **only data** — no function imports.
   182→   182→   182→
   183→   183→   183→**Design choice:** `SITES` lives in `types.ts` (not `sites/index.ts`) because the client UI (`page.tsx`) needs it for rendering badges, and importing from `sites/index.ts` would transitively pull in axios/playwright (Node-only).
   184→   184→   184→
   185→   185→   185→### `http.ts` — HTTP client with anti-bot headers + Playwright fallback
   186→   186→   186→
   187→   187→   187→**Role:** Shared HTTP layer for all HTML-based scrapers.
   188→   188→   188→
   189→   189→   189→**Key functions:**
   190→   190→   190→- `pickUserAgent()` — random from 5 browser User-Agents
   191→   191→   191→- `createHttpClient({ timeoutMs, referer })` — axios instance with realistic headers (Sec-Ch-Ua, Accept-Language, etc.)
   192→   192→   192→- `fetchHtml(url, opts)` — main fetcher:
   193→   193→   193→  - If `SCRAPE_USE_PLAYWRIGHT=1` → straight to Playwright
   194→   194→   194→  - Otherwise: axios → if blocked (status ≥ 400 or HTML contains "just a moment"/"cloudflare") → retry via Playwright
   195→   195→   195→- `parsePrice(raw)` — handles FR ("1 234,56 €"), DE ("1.234,56 EUR"), EN ("1,234.56"), Swiss ("CHF 1'234.50")
   196→   196→   196→- `absUrl(href, base)` — relative→absolute URL resolver
   197→   197→   197→- `cleanTitle(raw)` — collapse whitespace
   198→   198→   198→- `fetchJsonViaPlaywright(url)` — for JSON rendered inside `<pre>` (Cloudflare-protected APIs)
   199→   199→   199→- `fetchJsonPostViaPlaywright(apiUrl, opts)` — boots Chromium, solves Cloudflare, then runs `fetch()` inside `page.evaluate`
   200→   200→   200→
   201→   201→   201→**Design choices:**
   202→   202→   202→- Robots.txt **not consulted** (personal-use tool, not a public indexer — see file header)
   203→   203→   203→- `SCRAPE_JITTER=1` adds 200-700ms random delay to look human
   204→   204→   204→- Proxy support via `PROXY_URL` env (HTTP/HTTPS/SOCKS5)
   205→   205→   205→
   206→   206→   206→### `enrich.ts` — Product page metadata extraction
   207→   207→   207→
   208→   208→   208→**Role:** Fetches each product page and extracts structured `ProductMetadata`.
   209→   209→   209→
   210→   210→   210→**Key functions:**
   211→   211→   211→- `enrichProduct(p, signal)` — main entry, merges data from:
   212→   212→   212→  1. **JSON-LD** (`<script type="application/ld+json">` with `@type Product`)
   213→   213→   213→  2. **Microdata** (`[itemtype*=schema.org/Product]` + `itemprop`)
   214→   214→   214→  3. **Meta tags** (`og:brand`, `product:gtin`, etc.)
   215→   215→   215→  4. **Specs table** (`dl/dt/dd`, `table tr`, `.specs li`)
   216→   216→   216→  5. **Breadcrumb** (`schema.org/BreadcrumbList`)
   217→   217→   217→  6. **Variations** (color swatches, size selectors)
   218→   218→   218→- `guessBrandFromTitle(title)` — scans `KNOWN_BRANDS` list (100+ brands: Dynafit, Castelli, Shimano, etc.) + model→brand inference (e.g. "Speedgoat" → "Hoka")
   219→   219→   219→- `parseWeightGrams(raw)` — "850 g" / "1.2 kg" → grams
   220→   220→   220→- `extractColorsFromTitle(title)` — recognizes `/<color>` suffixes, `couleur: X` patterns
   221→   221→   221→
   222→   222→   222→**Design choices:**
   223→   223→   223→- Always returns an object (never throws) — on network failure, falls back to `guessBrandFromTitle(title)`
   224→   224→   224→- `ENRICH_TOP_N_PER_SITE = 6` — only top 6 per site enriched (performance)
   225→   225→   225→- Calls `classifyTaxonomy()` to normalize raw categories into consistent sport/category/subcategory/range
   226→   226→   226→
   227→   227→   227→### `matcher.ts` — Cross-site Union-Find matcher
   228→   228→   228→
   229→   229→   229→**Role:** Groups `ProductResult` entries from different sites into `MatchedProduct` (one logical product = multiple offers).
   230→   230→   230→
   231→   231→   231→**Matching cascade (in priority order):**
   232→   232→   232→1. **Strong ID** (EAN/GTIN/MPN ≥6 chars) → score 1.0, reason "ean"
   233→   233→   233→2. **Hard vetoes** (reject regardless of other scores):
   234→   234→   234→   - `gender-mismatch` — "Speedgoat 7 W" vs "Speedgoat 7 M"
   235→   235→   235→   - `product-line-mismatch` — GTX vs non-GTX, Mid vs Low, Pro vs base
   236→   236→   236→   - `model-version-mismatch` — Speedgoat 6 vs 7
   237→   237→   237→3. **Same-site cosmetic variant** — same brand + title Jaccard ≥ 0.85 → reason "cosmetic-variant"
   238→   238→   238→4. **Multi-criteria cross-site score** — brand 0.30 + category 0.20 + sport 0.15 + subcategory 0.10 + range 0.10 + title sim 0.15. Match if ≥ 0.55 AND title sim ≥ 0.4
   239→   239→   239→5. **Title-only similarity** ≥ 0.85 → reason "title-similarity"
   240→   240→   240→6. **Brand + model tokens** — same brand + Jaccard ≥ 0.5 → reason "brand+model"
   241→   241→   241→
   242→   242→   242→**Design choices:**
   243→   243→   243→- `STOP_TOKENS` strips FR/EN/DE color words, gender words, generic product nouns, outdoor colorway names
   244→   244→   244→- `stripColorSuffix(title)` truncates at last gender marker or first `/`
   245→   245→   245→- Union-Find with path compression
   246→   246→   246→- Results sorted by `siteCount DESC`, then `minPrice ASC`
   247→   247→   247→
   248→   248→   248→### `registry.ts` — Orchestrator
   249→   249→   249→
   250→   250→   250→**Role:** Runs all scrapers → enriches → matches.
   251→   251→   251→
   252→   252→   252→**Key functions:**
   253→   253→   253→- `aggregateSearch(query, opts)` — runs all scrapers in parallel
   254→   254→   254→  - HTTP scrapers: concurrent with random stagger (≤800ms)
   255→   255→   255→  - Playwright scrapers: limited to `MAX_PARALLEL_PLAYWRIGHT` (default 3) via worker-pool cursor
   256→   256→   256→- `aggregateMatched(query, opts)` — full workflow:
   257→   257→   257→  1. **Search phase** → `aggregateSearch()`
   258→   258→   258→  2. **Enrich phase** → `runPool(toEnrich, 8, enrichProduct)` (8 concurrent enrichments)
   259→   259→   259→  3. **Match phase** → `prepareItems()` → `matchProducts()`
   260→   260→   260→  4. Returns `{ products, filters, rawResults, phases: { searchMs, enrichMs, matchMs }, anySuccess }`
   261→   261→   261→
   262→   262→   262→**Design choices:**
   263→   263→   263→- `runScraperWithRetry` — aborts after `PER_SITE_TIMEOUT` (30s default, 60s for challenge sites); retries once if empty
   264→   264→   264→- `ScraperError` caught per-site — no error crashes the aggregate
   265→   265→   265→- **No demo fallback** — if all sites fail, response is empty
   266→   266→   266→- `DEBUG_DUMP=1` writes raw per-site JSON + `matched.json` to `debug/`
   267→   267→   267→
   268→   268→   268→### `filters.ts` — DynamicFilters builder
   269→   269→   269→
   270→   270→   270→**Role:** Builds facet lists for the UI sidebar from `MatchedProduct[]`.
   271→   271→   271→
   272→   272→   272→- `buildDynamicFilters(products)` — counts brands, categories, subcategories, sports, ranges, genders, colors, sizes, attributes, priceRange. Caps each list (e.g. brands.slice(0, 30)).
   273→   273→   273→- `normalizeSizeValue(raw)` — "42" → "eu:42", "US 10.5" → "us:10.5", "M" → "m"
   274→   274→   274→
   275→   275→   275→### `groups.ts` — Group management
   276→   276→   276→
   277→   277→   277→**Role:** Builtin group metadata + custom group persistence.
   278→   278→   278→
   279→   279→   279→- `DEFAULT_GROUPS` — derived from `BUILTIN_GROUP_META` + each `SITES[id].groups` field
   280→   280→   280→- `loadCustomGroups()` / `saveCustomGroups()` — localStorage persistence
   281→   281→   281→- `getSitesForGroup(groups, groupId)` — returns site IDs for a group
   282→   282→   282→
   283→   283→   283→**Design:** Adding a shop to a group = setting `groups: ["cycling"]` in `sites/<id>.ts`. No edit to `groups.ts` needed.
   284→   284→   284→
   285→   285→   285→### `sites/index.ts` — Barrel file + auto-derived lookups
   286→   286→   286→
   287→   287→   287→**Role:** Imports all 20 scrapers, derives lookups.
   288→   288→   288→
   289→   289→   289→- `SCRAPERS: Scraper[]` — array of all scrapers
   290→   290→   290→- `PLAYWRIGHT_SITES` — derived from `SCRAPERS.filter(s => s.capabilities?.usesPlaywright)`
   291→   291→   291→- `CHALLENGE_SITES` — derived from `SCRAPERS.filter(s => s.capabilities?.challenge)`
   292→   292→   292→- `SCRAPER_BY_SITE` — `Record<siteId, Scraper>`
   293→   293→   293→
   294→   294→   294→### `browserPool.ts` — Shared Chromium instance
   295→   295→   295→
   296→   296→   296→**Role:** Single Chromium instance with reusable per-call contexts.
   297→   297→   297→
   298→   298→   298→- `acquireContext(referer?)` — lazily launches browser, creates new `BrowserContext`
   299→   299→   299→- `releaseContext(context)` — closes context, keeps browser alive
   300→   300→   300→- Anti-detection: hides `navigator.webdriver`, fakes `navigator.languages`/`plugins`/`vendor`, spoofs WebGL
   301→   301→   301→
   302→   302→   302→**Design:** ~80 MB total memory instead of ~80 MB × N (one browser, N contexts).
   303→   303→   303→
   304→   304→   304→### `playwright.ts` — Playwright wrapper
   305→   305→   305→
   306→   306→   306→**Role:** Fallback for JS-rendered / Cloudflare-protected sites.
   307→   307→   307→
   308→   308→   308→- `fetchHtmlWithPlaywright(url, opts)` — 2 attempts; waits for challenge self-resolution (up to 12s), then races for product selectors
   309→   309→   309→- Anti-Cloudflare: never uses `networkidle` (Cloudflare keeps long-polling)
   310→   310→   310→
   311→   311→   311→### `taxonomy.ts` — Category normalizer
   312→   312→   312→
   313→   313→   313→**Role:** Normalizes raw category strings into consistent taxonomy.
   314→   314→   314→
   315→   315→   315→- `classifyTaxonomy(...inputs)` → `{ sport?, category?, subcategory?, range? }`
   316→   316→   316→- `SPORT_RULES` — 12 sports (Ski de randonnée, Alpinisme, Escalade, Trail, VTT, etc.)

   331→   331→   331→
   332→   332→   332→### `POST /api/search` — Main search endpoint
   333→   333→   333→
   334→   334→   334→**Request body:**
   335→   335→   335→```json
   336→   336→   336→{
   337→   337→   337→  "query": "castelli giro",

   342→   342→   342→
   343→   343→   343→**Response:**
   344→   344→   344→```json
   345→   345→   345→{
   346→   346→   346→  "query": "castelli giro",
   347→   347→   347→  "totalProducts": 15,
   348→   348→   348→  "products": [MatchedProduct, ...],
   349→   349→   349→  "filters": DynamicFilters,
   350→   350→   350→  "durationMs": 8234,
   351→   351→   351→  "phases": { "searchMs": 3200, "enrichMs": 4100, "matchMs": 934 },
   352→   352→   352→  "anySuccess": true,
   353→   353→   353→  "demo": false,
   354→   354→   354→  "sites": [{ "id": "all4cycling", "name": "All4cycling", "status": "ok", "count": 24, "durationMs": 2800 }],
   355→   355→   355→  "cached": false

   359→   359→   359→**Key behaviors:**
   360→   360→   360→- `query.length >= 2` required
   361→   361→   361→- `X-Custom-Groups` header: base64 JSON of user's custom groups (server can't read localStorage)
   362→   362→   362→- In-memory LRU cache (2-min TTL, 50 entries)
   363→   363→   363→- If group is selected but empty → short-circuits with empty response
   364→   364→   364→
   365→   365→   365→### `GET/POST/DELETE /api/groups` — Group management
   366→   366→   366→
   367→   367→   367→- **GET** → `{ groups: [...DEFAULT_GROUPS, ...customFromHeader] }`
   368→   368→   368→- **POST** `{ id, name, sites }` → validates, returns `{ group: ShopGroup }`
   369→   369→   369→- **DELETE** `?id=<groupId>` → refuses builtin groups

   463→   463→   463→
   464→   464→   464→### Architecture
   465→   465→   465→
   466→   466→   466→```
   467→   467→   467→extension/
   468→   468→   468→├── manifest.json              # MV3, devtools_page
   469→   469→   469→├── devtools.html/js           # Creates "Shop Protocol" DevTools panel
   470→   470→   470→├── panel.html/js              # Panel UI + capture logic
   471→   471→   471→├── protocol-generator.js      # Builds protocol.md from captured requests
   472→   472→   472→├── background.js              # Minimal service worker
   473→   473→   473→└── vendor/jszip.min.js        # Bundled JSZip for archive download
   474→   474→   474→```
   475→   475→   475→
   476→   476→   476→### Capture pipeline
   477→   477→   477→
   478→   478→   478→1. **Record** — `chrome.devtools.network.onRequestFinished` captures all XHR/fetch/WebSocket traffic
   479→   479→   479→2. **Categorize** — `isSearchRequest()` (sophisticated GraphQL-aware heuristic) / `isProductRequest()` (URL patterns) / WebSocket / Other
   480→   480→   480→3. **Filter noise** — 30+ filters for analytics, Shopify telemetry, app scripts, fonts, reviews
   481→   481→   481→4. **Auto-derive shop name** — from inspected tab URL via `chrome.devtools.inspectedWindow.eval`
   482→   482→   482→5. **Generate protocol.md** — markdown with: sample product, JSON-LD extraction, product card HTML, field list, WS frames
   483→   483→   483→6. **Download archive (.zip)** — protocol.md + capture.json + manifest.json + README.md + requests/ folder
   484→   484→   484→
   485→   485→   485→### Key heuristics
   486→   486→   486→
   487→   487→   487→- **GraphQL false-positive filtering** — distinguishes `query searchProducts(...)` from `query GetSlideCartOffers(...)` by inspecting operation names
   488→   488→   488→- **HTML response handling** — 50KB limit (was 5KB), JSON-LD ItemList extraction, product card HTML extraction, result count detection from `<title>`

   544→   544→   544→## 10. Key Design Decisions
   545→   545→   545→
   546→   546→   546→### 1. Drop-in scraper workflow
   547→   547→   547→Adding a shop = 1 file + 2 one-line edits. No Makefile/groups.ts changes needed.
   548→   548→   548→
   549→   549→   549→### 2. Capability-driven registry
   550→   550→   550→`PLAYWRIGHT_SITES`, `CHALLENGE_SITES`, timeouts — all derived from each scraper's `capabilities` field. No hard-coded lists.
   551→   551→   551→
   552→   552→   552→### 3. Three-phase pipeline
   553→   553→   553→Search → Enrich → Match, each timed. Enrichment bounded to top-N per site (perf); all products participate in matching.
   554→   554→   554→
   555→   555→   555→### 4. Union-Find matcher with hard vetoes
   556→   556→   556→Gender, product-line, model-version vetoes prevent false positives that pure weighted scoring would create.
   557→   557→   557→
   558→   558→   558→### 5. Client-side site filtering
   559→   559→   559→Toggling a site checkbox filters locally without re-fetching. `queryKey` excludes `selectedSites`.
   560→   560→   560→
   561→   561→   561→### 6. SITES in types.ts (client-safe)
   562→   562→   562→The `SITES` record contains only data (no function imports) so the UI can import it without pulling Node-only deps into the client bundle.
   563→   563→   563→
   564→   564→   564→### 7. Single shared Chromium
   565→   565→   565→One browser instance, reusable contexts (~80 MB total vs ~80 MB × N).
   566→   566→   566→
   567→   567→   567→### 8. No demo fallback
   568→   568→   568→If all sites fail, response is empty. Real errors shown.
   569→   569→   569→
   570→   570→   570→### 9. In-memory LRU cache
   571→   571→   571→2-min TTL, 50 entries. Reduces redundant scrapes during rapid UI interactions.
   572→   572→   572→
   573→   573→   573→### 10. Self-contained release
   574→   574→   574→`output: "standalone"` in next.config.ts. `build-release.sh` bumps 4 version files in lockstep.
